# Reply style and wording

- Keep every reply and report short and plain, like for an 8th grader. Answer, then stop.
- Go into detail only when something is risky for money, security or user data. Say that clearly and early.
- Never invent user-facing text. Use only wording the owner approved. Confirm exact copy and colors before writing code that uses them.
- Tone for user-facing text: warm and encouraging, never blunt or accusatory. Exact in fact: never soften a failure message so much it reads as success.
- Dates shown to users are always DD/MM/YYYY (see decisions/2026-10-18-date-format.md).
- Never compromise security or sound engineering for the sake of shorter replies.
